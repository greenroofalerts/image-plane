## Build order optimised for scale
1. **Close the join (F1):** cluster the ~16k unallocated into candidate visits (place+time) so corpus is whole. Serves all 14.
2. **Lee authors taxonomy (F2):** category list from his own labels. The gate everything waits on.
3. **Spread-label at scale:** model proposes → Lee corrects by voice → sprays to look-alikes → 85% agreement on held-back set 【411 P2 signal】. Taps bounded by distinct *situations*, not photos = the scale lever.
4. **Fork once:** F3 good/bad library + F4 diagnosis primitives, both reading the same labelled corpus.
5. **Then** build surfaces (packs, GRA triage, compliance PWA, report attribution, site card, moat) — thin readers, never re-label per surface.

**Principle:** build the labelled, job-joined corpus ONCE, prove on a held-back set, then every product is a thin read-layer.

- **Xero = ordering only, not display.** Use Xero to establish the ORDER events happened; never show invoice numbers/amounts on screen. **Install completion = the Xero line saying "BALANCE" or "final payment"** (Lee's rule). Later billed visits = maintenance 1, 2…; photos with no bill = diagnostic/⚠.
- **Plant-ID model — GET IT ("we are a plant business").** Species-accurate identifier: BioCLIP local on Mini A (sovereign, no key); Pl@ntNet API as optional accuracy upgrade. Prove accuracy on ~20 photos vs Lee's known species BEFORE mass-tagging. Species tag per photo.
- **Ellenberg indicator values = the environment read.** Identified species → their light/moisture/pH/fertility scores → infer the roof's conditions → recommend companion planting to lift ecology → into the report. (The rigorous version of the "muscari" trick.)
- **Weather-trend layer (per site + per region).** Open-Meteo historical rain/temp by site coordinates → seasonal trends & anomalies (drier springs, wetter winters, hot-peak summers) → explains why a roof looks as it does in the report AND what to plant for the trend. Regional rainfall map.
  - **Situationally-aware planting SPECIFICATION (Lee, 2026-07-01).** Same engine, second moment: at QUOTE/INSTALL time, move the spec from a generic standard mix to location-aware — spec what actually survives *this* site's rainfall/heat trend, cross-referenced with the corpus's record of what survived similar microclimates + Ellenberg fit. Turns weather-trend + survival-history + Ellenberg into a spec no competitor can write. Sharpens end-uses #17 (moat), #19 (planting guide), #20 (quoting aid). One intelligence, two moments: diagnose an existing roof, and spec a new one.
- **Scope of the other vision inferences:** KEEP species-count + biodiversity, but ONLY if scientifically robust (confident IDs, standard richness/diversity metrics, sampling bias noted). Other calls (weed/moss/corrosion/fire/solar/ponding/redaction) deprioritised by Lee.
