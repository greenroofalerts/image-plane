## Executive Summary

**Health grade: B.** For a 12-hour agent build this is unusually honest work:
the two founding hard rules — synthetic images only, no cloud calls — are
**verified intact** (no image ever committed, no DB present, all HTTP pinned to
127.0.0.1 via stdlib), and all 21 tests pass in 0.3s with real behavioural
assertions. The top risk is that the repo exists as a **single copy on this
laptop with no remote** — one disk failure erases it. Second: ingest is not
crash-proof against a real 15-year library — one unreadable file kills the
whole run with zero rows committed and re-crashes on every retry (empirically
proven), directly contradicting the README's "every stage can be killed and
re-run safely". Third: the caption command exits 0 even when 100% of rows
error, so an unattended overnight run can fail completely and look successful.
Top opportunities: a 5-minute `git push` closes the existential risk; ~1 day of
error-containment work makes the pipeline genuinely fit for the real Takeout
export; and defining a small read-only output contract lets captions serve both
the Memory Spine and LEE-483 without committing to either.

**Top 3 risks:** (1) single-copy repo, no remote; (2) poison-file ingest crash
+ silent-success caption runs — both bite on the first real library;
(3) Takeout sidecar naming variants silently dropping metadata at scale.

**Top 3 opportunities:** (1) push to a private remote today; (2) per-file
error containment + honest exit codes; (3) output contract (SQL view) feeding
LEE-391 spine and LEE-483 index.

## Phase 1 — Repo Map

**Purpose** — fully local photo-parsing pipeline: walk a photo export, store
normalised metadata in SQLite, find exact/near duplicates, caption every image
with a local Ollama vision model. Feeds a planned green-roof evidence layer
(README.md:117-120).

**Stack** — Python ≥3.11, Pillow (+optional pillow-heif), stdlib sqlite3 and
urllib; pytest. One runtime dependency total (pyproject.toml:6-8). Vendored
Ollama 0.30.7 in `bin/` (503 MB, gitignored).

**Entry point** — `image-plane` console script → `image_plane.cli:main`
(pyproject.toml:14-15), subcommands `ingest | dedup | caption | status`
(cli.py:33-48).

**Core flow** — `ingest_folder` walks + sha256 + 64-bit dHash + EXIF/sidecar
metadata → `photos` table (ingest.py:206-232, db.py:17-35) → `find_duplicates`
rebuilds the `duplicates` table from stored hashes, exact=sha256,
near=hamming≤8 (dedup.py:30-70) → `caption_pending` sends each uncaptioned row
to localhost Ollama, JSON caption + tags written back per-row
(caption.py:50-100, ollama_client.py:94-118).

**Conventions** — small modules, one concern each; logging not print inside
library code; docstrings state resumability contracts; tests generate all
fixtures per-session, nothing binary committed (conftest.py:13-20).

**Surprising** — (1) git author on all commits is the trading-stack identity
"Glide Trader" (F11); (2) `bin/` also contains MLX metal libs — it is the
stock Ollama 0.30.7 distribution, unmodified; (3) repo dir is 503 MB but the
git repo is only 248 KB.

**State** — 4 commits, branch `main` only, **no remote**, working tree clean.

## Phase 2 — Audit findings

Severity legend (Lee's order): S1 data-rule violation · S2 silent failure ·
S3 report/code mismatch · S4 single-copy risk · S5 maintainability · S6 style.

### Hard-rule verification (the part that matters most)

- **No real photos: VERIFIED.** FACT — no image file in git history or working
  tree; no SQLite DB exists; fixtures are deterministic synthetic scenes
  (generate_test_images.py:45-81); fixture GPS/timestamps are arbitrary
  constants (BASE_TS 2023-11-14, generate_test_images.py:26), not real EXIF.
- **No cloud calls: VERIFIED.** FACT — all egress is `127.0.0.1:11434`
  (ollama_client.py:16); the only true network path is model download, which
  the localhost Ollama daemon performs when explicitly asked via `--pull`
  (cli.py:44-45, caption.py:42-47). Documented in README.md:6-8.

### Findings

**F1 · S2 · NEW · FACT (empirically proven) — One bad file makes ingest
permanently unable to complete, losing all uncommitted work.**
`sha256_file` (ingest.py:49-54) is called at ingest.py:147 outside the
try/except (which only wraps `Image.open`, ingest.py:152-159); the folder loop
(ingest.py:225-229) has no per-file containment; `path.stat()` at ingest.py:175
can also raise on a vanished file. Proven: chmod-000 file → PermissionError
traceback, exit 1, **0 rows committed** (commit interval is 100,
ingest.py:227-230 — everything before the poison file was lost too). Re-run
crashes at the same file. A 15-year Takeout export will contain unreadable,
truncated and mid-sync files; this is near-certain to fire. Also falsifies
README.md:61 (S3 facet).

**F2 · S2 · NEW · FACT (empirically proven) — Caption run that fails 100% exits
0 and looks successful.** cli.py:65-75 never inspects `stats["errors"]`;
`return 0` is unconditional (cli.py:85). caption_pending (caption.py:67-90) has
no abort-after-consecutive-failures, so Ollama dying mid-run produces a
warning-per-row "successful" run. Verifier widened it: passing `--model`
explicitly **bypasses the server-liveness check entirely** (cli.py:66 only
calls `ensure_vision_model` when `--model` is absent) — proven: dead server +
`--model x` → `{'captioned': 0, 'errors': 2}`, exit 0. Any future cron/launchd
wrapper would report green on a totally failed overnight run.

**F3 · S3 · NEW · FACT — README setup cannot work from a fresh clone.**
README.md:77-79 says `./bin/ollama serve`, but `.gitignore:2` excludes `bin/`
(confirmed: `git ls-files` tracks 17 files, none under bin/). No instruction
anywhere for re-obtaining the binary (version 0.30.7 is named only in
BENCHMARK.md:3). Latent today (no clone target exists — see F4) but it means
the repo is not rebuildable from git alone.

**F4 · S4 · NEW · FACT — Single copy of the repo, no remote.** `git remote -v`
empty; 4 commits; main only. The git repo is 248 KB — pushing costs minutes.
Until then, one laptop disk failure erases the project. (bin/ and model weights
are re-downloadable; the *code and docs* are not.)

**F5 · S3 · KNOWN (LEE-411) · FACT — Built against an issue that says don't
build.** README.md:1 and all 4 commit subjects cite LEE-411, whose status reads
"Capture only. Do not build." Also KNOWN: no dedicated Linear issue exists for
this repo at all. The work is good; the paper trail is wrong. Fix is a Linear
correction + tracking ticket (drafted in Phase 4), not a code change.

**F6 · S5, borderline S2 at scale · NEW · FACT (code) + asserted (Takeout
behaviour) — Sidecar lookup misses known real-world Takeout naming variants,
silently dropping metadata.** find_sidecar (ingest.py:57-68) checks exactly
three patterns (`X.json`, `X.supplemental-metadata.json`, `X.suppl.json`).
Real Takeout exports also produce: duplicate-counter forms where
`IMG_001(1).jpg` pairs with `IMG_001.jpg(1).json`; `-edited` images that share
the original's sidecar; and sidecar names truncated at the 46/51-char filename
limit (these specifics are documented Takeout behaviour, not verifiable from
this repo). A miss falls through silently to EXIF (ingest.py:161-163) — and
Takeout strips GPS from EXIF (the repo's own docstring, ingest.py:8) — so the
row ingests with NULL taken_at/GPS and nobody is told. At 15-year-library
scale, thousands of rows. The planned GPS+date site-matching (README.md:118-119)
is exactly what this silently degrades.

**F7 · S5 · NEW · FACT — Malformed captions are stored permanently with no way
to find or retry them.** On non-JSON model output, raw text (≤500 chars) is
stored as the caption (ollama_client.py:121-134); caption only processes
`WHERE caption IS NULL` (caption.py:57); the schema (db.py:16-47) has no
quality/flag column, and `tags='[]'` is ambiguous (valid responses can also
have empty tags). Logged at write time (ollama_client.py:133) so not silent,
but unfindable a week later.

**F8 · S5 · NEW · JUDGEMENT — Near-dupe storage is pairwise edges, not groups;
the approved quarantine feature needs groups.** dedup.py:58-65 inserts one edge
per qualifying pair: a chain A~B~C yields B→A and C→B; a triangle gives C two
different `dup_of` parents (both persist — UNIQUE at db.py:45 includes
`dup_of`). The dedup docstring's "earliest-ingested row is kept as canonical"
(dedup.py:9-10) is true only for exact dupes. The agreed next feature —
best-of-group quarantine (README.md:113-116, QUESTIONS-FOR-LEE.md:17-19) —
needs transitive group semantics the schema doesn't express. Derivable at read
time via union-find; decide before building the quarantine command.

**F9 · S5 · NEW · FACT — EXIF timestamps mislabelled as UTC.** EXIF
DateTime/DateTimeOriginal are local naive wall-clock per the EXIF spec, but
ingest stamps them `tzinfo=timezone.utc` (ingest.py:123-129). Takeout-sourced
rows are unaffected (sidecar epoch is true UTC, ingest.py:82, and wins at
ingest.py:163). For icloud-sourced rows, future date-based site-matching can
skew by hours. Cheap to document now, cheap to fix later.

**F10 · S6 · NEW · FACT — Source auto-detect flips on any stray JSON.**
detect_source (ingest.py:198-203) returns "takeout" if *any* non-metadata.json
JSON exists anywhere under the folder. Low impact (sidecar lookups simply find
nothing) but the `source` column becomes wrong, and on a JSON-free icloud
export it walks the whole tree before concluding.

**F11 · S6 · NEW · FACT — Wrong git identity.** All 4 commits authored
"Glide Trader <trader@glide.com>" — the trading-stack identity. Cosmetic, but
worth a repo-local `git config user.*` before history grows.

**F12 · S6 · NEW · FACT — "Nothing else on the machine touched" is slightly
false.** README.md:128-129; model weights live in `~/.ollama` (3.0 GB),
outside the repo. One honest sentence fixes it.

**F13 · S5 · NEW · JUDGEMENT — No failure visibility for unattended runs.**
All signalling is stdout/log lines; nothing writes anywhere observable
(the agent_events table drafted elsewhere in LeeOS is not yet applied, so
there is nowhere to write today). Combined with F2, an overnight chunked
caption run can fail invisibly. A summary line + nonzero exit (F2 fix) is the
minimum; a notification hook is optional later.

**F14 · Context · FACT — Disk is genuinely tight.** 14 GB free on this machine
at audit time; README.md:19-22 and QUESTIONS-FOR-LEE.md:6-9 already flag this.
The repo's own rule — check free space against export size before ingesting —
is live and binding.

## Phase 3 — Strategy

**Theme 1: Existence insurance (M0).** Target state: the repo survives the
loss of this laptop. Private remote, push main + this audit branch; document
bin/ provenance (Ollama 0.30.7, download URL + version pin) so a fresh clone
is rebuildable; fix git identity. Done when: `git remote -v` shows a remote,
CI-free push succeeds, README setup works from a clean clone (binary re-fetch
step included).

**Theme 2: Survive the real library (M1).** Target state: pointing ingest at
a hostile 15-year Takeout export completes, always, with a per-file error
ledger instead of crashes. Per-file containment, commit cadence that can't
lose >1 file of work on crash, sidecar variant coverage, honest exit codes and
end-of-run summaries (X failed, Y missing metadata). Done when: a fixture
folder seeded with poison files (unreadable, vanishing, truncated, "(1)"
sidecars) ingests to completion with correct counts, and a dead-Ollama caption
run exits nonzero.

**Theme 3: Output contract — where Image Plane flows (M2).** Image Plane has
two queued consumers: Memory Spine observations (LEE-391) and the visual
precedent library index (LEE-483); State of Play (LEE-519) already lists it as
a vertical. Target state: commit to neither yet, but expose one stable,
read-only surface both can build on: a documented SQL view (e.g.
`v_photo_observations`: path, taken_at, gps, caption, tags, dup_status,
source) + a one-page contract doc stating column stability guarantees. The
SQLite file is the API; the view is the contract. Done when: the view exists,
is tested, and the contract doc names both consumers and what each would need
next (spine: observation rows per captioned photo; LEE-483: search over
caption+tags). No exporter is built until one consumer is chosen.

**Theme 4: Truthful paper trail (M0/M1).** Target state: Linear matches
reality. Tracking ticket filed (draft below), LEE-411 status corrected, this
audit linked. Done when: the drafted ticket exists in Linear and LEE-411 no
longer says "do not build" about a thing that is built.

**NOT fixing (deliberate):**
- Dedup O(n²) — measured fine to 200k photos (~49 min); the docstring's
  bucketing escape hatch can wait until it actually hurts.
- Sharding/parallel captioning across Minis — Lee decided 7 s sequential
  overnight chunks are fine (QUESTIONS-FOR-LEE.md:11-12).
- Model upgrade (7B/qwen3-vl) — disk-bound decision already made and
  documented; revisit only if caption quality fails on real photos.
- Near-dupe threshold tuning — meaningless on synthetic images; waits for
  real photos by design (QUESTIONS-FOR-LEE.md:17-19).
- HEIC testing — explicitly sequenced to when the real export lands (Lee's
  decision #6).
- agent_events integration — the table isn't applied anywhere yet; F13's exit
  codes + summary are sufficient until LeeOS-wide eventing exists.

### Implementation sketches (top 3)

**T4 sketch** — wrap the whole per-file unit, not just Image.open:
```python

    try:
        result = ingest_file(conn, path, source)

        result = "error"
        failures.append((str(path), repr(e)))
    counts[result] += 1
    if i % progress_every == 0:
        conn.commit(); log.info(...)
```
Inside ingest_file, move `sha256_file` and `path.stat()` inside the existing
try (or rely on the outer boundary). Lower `progress_every` commit interval to
25, or commit-per-file behind a `--durable` flag if 100-file loss windows

New tests: chmod-000 file (skip on CI-less mac is fine — it runs locally),

sha256_file), truncated JPEG bytes.
