required a word boundary before the outward code and silently dropped every postcode
concatenated directly onto the preceding word with no space — a common pattern in this
table's address strings (e.g. `"Co DurhamDL2 1TS"`, `"KentDA13 0NP"`, 89 such rows
corpus-wide). Fixed by dropping the leading `\b` (trailing boundary kept). This alone moved
the known_entities strict-set count from 233 to 260 distinct refs (inventory doc's own count
was 259 — 1 off, immaterial, same class of rounding the inventory doc itself flagged
elsewhere as immaterial).

## Step 2: rerun gps_nn against the grown map

Script `f2_rerun_gps_nn_m3.py` — copy of F2-M1's `f2_rerun_gps_nn.py` with three deltas
required by this pass's spec (all documented in the script's own docstring):
1. Method tag suffix `_f2` → `_f2m3` (`gps_nn_f2m3`, `date_split_f2m3`, `date_nearest_f2m3`).
2. Date derived strictly from the path's `/YYYY/MM/DD/` segment (regex on the path itself,
   not just trusted from `kept_deduped.jsonl`); a photo where that fails to parse — and the
   kept_deduped fallback also has nothing — is **never written**, goes to residue instead.
   Result this pass: **0 undatable residue** (every candidate photo's path parsed cleanly).

   script hardcoded a reference to `f2_map_growth_dryrun.json`'s 11 refs, which would have
